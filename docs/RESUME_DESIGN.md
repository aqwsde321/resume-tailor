# 내 이력서 화면 디자인

## 적용 스킬

- [frontend-design](https://github.com/anthropics/skills/tree/main/skills/frontend-design): 작업의 성격에 맞는 시각적 방향, 글자 크기, 배치와 일관된 색상 체계
- [web-design-guidelines](https://github.com/vercel-labs/agent-skills/tree/main/skills/web-design-guidelines): 입력·포커스·키보드·모바일·접근성 검토

두 스킬은 사용자 스킬 폴더에 설치한다. 저장소에는 설치된 스킬이나 개인 자료를 복사하지 않는다.

## 방향

이력서의 긴 문장을 읽고 고치는 문서 작업 공간이다. 장식용 이미지나 통계 대신 실제 문서와 수정 댓글이 중심이 된다. 등록 전 화면과 문서 검토 중 화면의 밀도를 다르게 한다.

- 배경 `#F5F6FA`, 문서 `#FFFFFF`, 본문 `#202536`, 보조 글자 `#626B7E`, 구분선 `#DEE2EB`, 강조 `#6554C0`
- 한글 본문은 Apple SD Gothic Neo / Noto Sans KR / 시스템 글꼴을 사용한다. 외부 폰트 요청 없이 글자 크기·행간·굵기로 제목과 본문을 구분한다.
- 모든 본문은 왼쪽 정렬한다. 문서는 긴 단락을 읽기 좋은 폭으로 제한하고 댓글은 별도 좁은 열에 둔다.
- 왼쪽 탐색 216px, 가운데 문서 영역, 필요할 때 여는 오른쪽 댓글 목록. 목록이 닫히면 문서 영역을 넓게 사용한다. 작은 화면에서는 메뉴를 가로로 접고 댓글 목록을 문서 아래에 배치한다.
- 보라색은 활성 메뉴·주요 실행·선택 표시로 한정한다. 같은 모양의 카드가 화면 전체에 반복되지 않게 한다.

```text
탐색 메뉴 | 현재 위치 / 자동 저장 상태
          | 내 이력서                     현재 상태
          | 자료 등록 → 원문 검토 → 이력서 확정
          | 등록 전: 입력 영역             사용 안내
          | 검토 중: 원문 문서             수정 댓글
          | 정리 옵션                     다음 실행
```

## 범위와 검증

첫 적용 대상은 `/workspace/resume`이다. 회사별 이력서와 설정의 기존 작업 흐름을 유지한다. 공통 입력·검토 컴포넌트는 명시적으로 디자인 변형을 선택하도록 한다.

키보드로 입력 방법을 전환하고 오류가 난 입력으로 이동할 수 있어야 한다. 긴 파일명과 본문은 가로 스크롤을 만들지 않는다. 포커스 표시, 이동 링크, 비동기 상태, 대비와 동작 감소 설정을 확인한다.

사용자 지침에 따라 자동 E2E와 정적 검사로 검증하며, 직접 브라우저 조작이나 스크린샷 시각 검증은 수행하지 않는다.

## 적용 후 코드 검토

- `src/features/workspace/ui/source-input.tsx`: 탭과 입력 필드 ID 분리, 방향키·Home·End 이동, 입력 오류 포커스와 설명 연결 확인
- `src/features/workspace/ui/workspace-shell.tsx`: 본문 이동 링크·활성 메뉴·자동 저장 상태·장식 아이콘 접근성 확인
- `src/features/workspace/ui/document-editor.tsx`: 보기 방식 선택 상태, 댓글 입력 라벨, 키보드 선택 처리, 문서 포커스 표시 확인
- `src/features/workspace/workspace.css`: 디자인 범위 한정, 긴 문서 줄바꿈, 작은 화면 댓글 배치, 포커스·호버·동작 감소 설정 확인
- `src/features/workspace/ui/resume-preview.tsx`: 실제 저장 데이터만 표시하며 이름·기간·연락처·프로젝트 기술·학력·자격을 유지

코드 검토와 자동 배치 검증은 시각적 완성도를 직접 확인하는 검증을 대신하지 않는다. 원본 이미지의 정적 크기 메타데이터는 기존 추출 데이터에 없어 이번 디자인 변경에 포함하지 않았다.

검증 결과: 단위·API 208개, E2E 27개 통과. 타입 검사·프로덕션 빌드 통과. 린트는 오류 없이 기존 경고 2건. 키보드 입력 탭 이동, 오류 입력 포커스, 390px 화면의 긴 문서·파일명과 댓글 배치, 직접 편집·댓글 반영·경험 보완 흐름을 자동 검증했다.

## 선택 위치에서 댓글 작성

- 문장 선택만으로 입력창을 열지 않는다. 선택 끝부분 가까이에 댓글 버튼을 표시하고, 버튼을 누른 경우에만 작성창을 연다.
- 작성 중인 문장은 임시 강조로 유지한다. 등록하면 하이라이트와 작은 표시를 남기고, 취소하면 임시 표시를 제거한다.
- 등록된 표시를 누르거나 키보드로 활성화하면 해당 댓글 목록을 연다. 활성 댓글만 더 진하게 표시한다.
- 작성창은 스크롤·창 크기 변경 시 위치를 갱신하고 화면 경계를 벗어나지 않게 제한한다. 모바일은 하단 작성창을 사용한다.
- 댓글 목록은 기본적으로 닫는다. 여러 댓글의 AI 일괄 반영과 개별 변경 수락·되돌리기는 유지한다.
- Escape 또는 취소로 작성을 닫고, 문서 전체 댓글과 선택 영역 댓글 버튼을 키보드 대안으로 제공한다.
- 자동 E2E에서 두 댓글 일괄 반영, 모바일 작성창 범위·포커스, 취소, 등록 후 새로고침, 표시의 키보드 재열기를 검증한다. 실제 터치 기기의 선택 핸들과 수동 시각 검증은 수행하지 않았다.
